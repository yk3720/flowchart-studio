# 改造案 — OCC（楽観ロック）と stale 時の保存拒否

**状態:** 草案（未実装 · 2026-07-08）  
**由来:** プロダクトレビュー（Web 調査 + 4 視点サブエージェント）の推奨一手  
**関連:** [現状とロードマップ.md](./現状とロードマップ.md) · [UI仕様.md](./UI仕様.md) · ADR-013 · ADR-015 · [DB設計.md](../03_技術仕様/DB設計.md)

---

## 1. 目的

課内で複数 editor が同じ動作を開いたときに起きる **黙った上書き** と、再生成前の表のままクラウドに載る **表↔図の不整合** を止める。

リアルタイム共同編集（カーソル共有・OT/CRDT）にはしない。

---

## 2. 現状の問題

| # | 現象 | 影響 |
|---|------|------|
| A | `saveFlowDocument` が版比較なしで upsert（last-write-wins） | 後着の保存が相手の表を黙って上書き |
| B | PNG/SVG は `isStale` でブロックするが、**保存は stale でも通る** | DB に「表は新・図スナップショットは旧」が残る |
| C | 保存成功の楽観確定（UI 先行 · クラウド fire-and-forget） | 失敗しても「保存済み」に見える余地 |

---

## 3. 改造内容

### 3.1 OCC（Optimistic Concurrency Control）

1. 読込時に `flow_documents.updated_at`（または同等の世代）をクライアントが保持する  
2. 保存時にサーバー／Supabase で `eq(updated_at, expected)` を条件にする  
3. 不一致なら保存失敗（409 相当）→ UI で「他の人が更新済み。読み直してから」＋再読込導線

**やらない:** OT / CRDT / 自動マージ / ライブカーソル

### 3.2 stale 時は保存も拒否

PNG/SVG と同じく、`jsonText !== committedJson`（stale）のときは **保存ボタンを無効化**し、理由をツールチップ／バナーで示す。

**代替案（採用時は ADR）:** 保存時にサーバー側で表から再生成してから書く（SoT を表に一本化）。本草案の既定は **拒否（クライアント契約の統一）**。

### 3.3 保存成功の確定タイミング（同梱推奨）

クラウド結果を await し、**成功時のみ** `savedJson` を更新。失敗時は dirty 維持＋再試行。

（OCC・stale 拒否と別 PR でも可。壊れる経路が近いので同梱を推奨。）

## 4. 進めたあとに変わること / 変わらないこと

### 変わること

| 場面 | 変化 |
|------|------|
| 同時編集 | 先に誰かが保存していたら、後着は失敗して読み直しを促される（黙った上書きが止まる） |
| 表だけ直した直後 | 再生成するまで保存できない（古い図つきのまま DB に載らない） |
| 一人編集の平常 | 再生成→保存の既存手順がそのまま正になる |

### 変わらないこと

- 社内合意（有償・データ外部保存）の可否判断  
- 取込 CTA・コメント共有導線・装置単位 ACL・RPC サイズ上限など（別改造）  
- 見た目・レイアウト・リアルタイム共同編集 UX

## 5. 受け入れの目安

| # | 条件 |
|---|------|
| AC-1 | 二タブで同一モジュールを開き、片方保存後にもう片方が保存すると衝突エラーになり、黙って上書きされない |
| AC-2 | 表編集後・再生成前は保存不可（または同等の拒否メッセージ） |
| AC-3 | 再生成後は従来どおり保存できる |
| AC-4 | クラウド保存失敗時は dirty が残り、「保存済み」に見えない |
| AC-5 | Vitest または E2E で AC-1〜2 相当を少なくとも 1 本ずつ固定 |

## 6. 実装メモ（着手時の当たり）

| 層 | 候補 |
|----|------|
| UI | `FlowchartEditor` の `handleSaveModule` · `isStale` · 保存ボタン disabled |
| Server | `saveFlowDocument`（updated_at 条件 · 衝突レスポンス） |
| DB | 既存 `updated_at` の利用確認（足りなければ migration） |
| テスト | OCC 衝突 · stale 保存拒否 · 保存失敗時 dirty 維持 |

実装確定時は ADR（競合解決）と [UI仕様.md](./UI仕様.md) の保存契約を同ターンで更新する。
