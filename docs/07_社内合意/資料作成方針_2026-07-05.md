## 2. 判断依頼の論調（最重要）

### 聞くこと（面談前 · 2点のみ）

金額の許可は **聞かない**。以下の Yes/No のみ。

1. **有償プラン（外部クラウドの有償利用）を使ってよいか**
2. **社内設計データを外部クラウドに保存してよいか**（データの範囲は §3 参照）

### 聞かないこと（この段階では）

- 「月いくらまで OK か」といった **予算上限の承認**
- 会社名義契約 · ログイン要否の細部（有償 OK 後に十分）
- 構成 A/B/C/D の記号での選び方（上司向け図解では出さない）

### 意図

有償 SaaS そのものの可否が先。具体的な月額は **判断依頼ではなく参考情報** として載せ、上司が「だいたいいくら？」と思ったときにすぐ答えが見えるようにする。早急な金額提示は反発を招きうるため、**聞き方と載せ方を分離**する。

## 3. データの範囲と Supabase の位置づけ

フローチャート作成ツールに載るデータについての判断。

### 含める想定（社内設計データ）

- フロー表
- 社内番号 · 装置名
- PLC コメント等（フローチャート作成に必要な社内設計データ）

### 含めない想定

- **客先名 · 契約情報など社外秘** — 正しい使い方をする限りデータに含まれない、と判断した。

### ログイン · Supabase

課内で使うツールとして **ログイン認証が必要**。誰のデータか分けるため。  
その **認証の代行とデータ保存** に Supabase を選んでいる、と簡潔に説明する。

### 図解への載せ方（文案たたき台）

ご判断の **直前** に短い補足ボックス（3〜4 行）を置く想定:

> **保存するデータ:** フロー表 · 社内番号 · 装置名 · PLC コメント等（フローチャートに必要な社内設計データ）。客先名 · 契約情報等の社外秘は含めない想定。  
> **ログイン:** 課内利用のため認証が必要。認証と保存に Supabase を使う想定（有償プラン検討時）。

ご判断②の例: 「上記の範囲の社内設計データを、外部クラウドに保存してよいか」

**図解上の位置:** `ask` 直前の `data-context` セクション（2026-07-05 確定）。

### 面談に回すもの

- 装置名の付け方で客先が推測される場合の運用ルール（01 §7 と同旨 · 図解には長く書かない）

## 4. 金額の載せ方

| 項目 | 方針 |
|------|------|
| **ラベル** | **参考：有償を検討する場合の月額イメージ**（判断依頼ではない、と分かる文言） |
| **載せる数** | **ログインあり · 推奨構成の Max（上限）のみ** — レンジや「ログインなし」案は載せない |
| **内訳** | 4 サービス表に **サービス別の目安月額** を足す（GitHub は無料枠可 → $0 等と明記） |
| **注記** | 「本番に載せる機能を絞れば、目安はさらに下がる」 |
| **ご判断・choice** | **金額を入れない**（目安は `why-paid` の参考欄に集約） |

### 伝えたいこと

今回挙げている有償プランは、**作者がベストと考える仕組み（ログインあり本番）を実現する場合に実現可能性が高い**、という話。機能を削れば費用も下がる。

### 数値の正本

試算の詳細は 01 §3 · 03 · 04。上司向け図解の Max は構成 B 想定（月 約 $50 · 約 7,500 円目安 · 為替 150 円）。
