フローチャート作成ツール — 進め方のご相談

制御フローが100個・5ファイルに増え、「どのファイルのどのシートか」を探すたびに作業が止まる負担をきっかけに、 表から自動で描く Web ツール（Flowchart Studio）を検討している。 本日お願いしたいのはすぐ作り始める許可ではなく、進め方の方向性を一緒に決めていただくことである。

いまの状況

  1. 1. 経緯：フローが増えるほど「保存場所を特定する」確認が重くなり、Web で整理・再描画できる形を検討し始めた。
  2. 2. 進捗：試作版は動作中。個人検証用の無料枠で、作成 · 保存 · 書き換え再描画 · 装置ごとの整理ができる。
  3. 3. 位置づけ：まず1か月の無料試用で現場で回せるか確認する。有料移行の可否は試用後に係長の判断をいただく。
  4. 4. 本番運用：成功条件を満たした段階で、有償クラウド（後述 4 種）への移行を検討する見込み。
  5. 5. 有償が難しい場合：画面や入力の仕組みは維持し、データベースを使わない構成へ切り替えて再検討する。

なぜ Web アプリか

探す負担

装置やユニットごとに整理しても、「どのファイルのどのシートか」を追う作業は残る。作る側 · 見る側の双方に負担がかかり、改善に回す時間が削られる。

Excel との位置づけ

Excel も有効である。ただフローが 100 個 · 5 ファイル規模では、探索と反映がボトルネックになりやすいと感じている。

Web の利点

一覧から該当フローを開き、表を書き換えれば再描画してすぐ反映できる。探す手間を減らし、作業にすぐ入れる状態を目指す。

試用の進め方（1か月）

ベスト案は、無料プランで試し、下記 3 点を満たしたら有料移行の検討フェーズに進む流れである。

  1. フローの保存 · 再編集が、現場で滞りなくできること
  2. 「どのファイルか探す」作業が、試用前より明らかに楽になっていること（探索時間は試用中に計測）
  3. Excel → JSON の取込が、想定どおり回ること

データの扱い（試用期間）：機密度の低いデータに限定。保存先は Supabase 無料枠（個人メール）で、検証目的の暫定対応である。本番では会社アカウントとアクセス制御へ切り替える前提。

Excel 連携：作者 PC の変換 exe で JSON 化 → Web に取込。すでにこの経路は使える。運用が増えて大変にならないか、への回答とする。

なぜ有料サービスが必要か（本番化の場合）

試用成功後の本番化を検討する段階の話である。本日の判断依頼ではない。 いまの URL は個人検証用の無料枠（月 0 円）で、課内の正式ツールとして使い続けるには向かない。

定着した場合の変化

一覧 → 編集 → 反映

一覧から該当フローがすぐ開き、編集して保存すればすぐ反映される。これが当たり前になる。 「保存場所を探して手が止まる」状態から、作業にすぐ入れる状態へ移ることが、いちばん大きな変化と考えている。

ご判断いただきたい点

本日いちばんお願いしたいのは（1）である。（2）（3）は、有料移行や代替案に進むときの方針の事前了承としてお聞きしたい。 1か月後の最終判断は、その時点で改めてご相談する。

  1. 無料プランでの試運用を開始してよいか
  2. 成功条件を満たした場合、有料プランへの移行を「検討フェーズ」に進めてよいか
  3. 有料が難しい場合、DB を使わない構成へ切り替える方針でよいか
